# 04 多表关联分析

---

## 1. 订单表 + 用户表关联分析
### 分析思路
通过 `INNER JOIN` 将订单表与客户表以 `customer_id` 为关联键进行内连接，筛选订单核心信息与用户基础信息，使用 `LIMIT 20` 预览关联后的数据结构、字段匹配度与内容格式，验证表间关联逻辑是否正确，为后续订单地域分布、用户画像分析提供数据支撑。

### 分析结论
订单与支付表关联预览结果显示，数据格式规范，无缺失值、乱码等异常，表间关联逻辑验证通过。所有订单状态均为 `delivered`（已交付），属于有效交易订单；支付方式以 `credit_card`（信用卡）为主，同时包含 `boleto`（票据支付）、`voucher`（代金券）等类型，与平台整体支付结构特征一致；支付金额分布区间合理，无明显异常值。数据质量良好，可直接用于后续支付维度的深度分析。

---

## 2. 订单表 + 支付表关联分析
### 分析思路
通过 `INNER JOIN` 将订单表与支付表以 `order_id` 为关联键进行内连接，筛选订单核心信息与支付方式、支付金额数据，使用 `LIMIT` 预览关联后的数据结构与字段匹配情况，验证表间关联逻辑，为后续支付方式分布、客单价分析提供数据支撑。

### 分析结论
绝大多数订单都有对应的支付记录，支付方式以信用卡为主，其次是 boleto（巴西银行转账）和代金券，与前期单表分析的支付方式分布完全吻合。订单支付金额与订单状态匹配合理，无异常金额数据。

---

## 3. 订单表 + 订单项表 + 商品表关联分析
### 分析思路
通过 `INNER JOIN` 实现订单表、订单项表与商品表的逐级关联，以 `order_id` 完成订单与订单项的匹配，再以 `product_id` 完成订单项与商品信息的匹配，从而整合订单、商品、价格及品类全维度数据，通过预览结果验证表间关联逻辑是否准确，为后续商品销售与品类分析奠定数据基础。

### 分析结论
三表关联查询结果规范完整，表间关联关系清晰有效，订单、订单项、商品及品类信息能够精准对应，充分体现了一单多品的真实业务特征。查询结果包含多元化的商品品类，与平台整体商品结构保持一致，商品价格分布合理且无异常数值，整体数据质量可靠，可直接用于商品销量统计、热销品类分析等后续探索性分析工作。

---

## 4. 订单表 + 评价表关联分析
### 分析思路
通过 `LEFT JOIN` 将订单表与评价表以 `order_id` 为关联键进行左连接，保留全部订单数据并匹配对应的用户评分，通过预览结果验证表间关联逻辑，同时观察订单状态与评价分数的对应关系，为后续用户满意度与评价分布分析提供数据支撑。

### 分析结论
订单与评价表关联结果显示，表间关联逻辑有效，所有订单数据均被完整保留，订单状态与用户评价信息匹配正常。预览数据中大部分订单均已产生用户评价，评分集中在高分段，同时也存在少量中低分评价，整体数据格式规范，无缺失或异常情况，可直接用于后续用户满意度分析工作。

---

## 5. 订单 + 用户 + 支付 + 订单项 + 商品五表关联分析
### 分析思路
将订单、用户、支付、订单项、商品五表进行全链路关联，查看订单的完整信息链路，包括用户地域、支付方式、支付金额、商品价格和品类，建立订单的全维度画像。

### 分析结论
五表关联结果验证了各表之间的关联关系完整，数据一致性良好。订单的用户地域、支付方式、商品品类等信息相互匹配，没有出现矛盾或异常数据。例如，来自圣保罗州的用户主要使用信用卡支付，购买的商品以家居用品、美妆健康等热门品类为主，符合前期单表分析的结论。

---

## 本章小结
通过多表关联分析，验证了各业务表之间的关联关系完整、数据一致性良好，建立了订单从用户下单到支付、购买商品、用户评价的全链路数据视图。这为后续基于多维度的业务分析（如不同地域用户的支付习惯、不同品类商品的用户满意度等）打下了坚实基础。
