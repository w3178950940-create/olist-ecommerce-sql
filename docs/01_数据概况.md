# 01 数据概况

---

## 1. 订单状态
### 分析思路
使用 `DISTINCT` 对 `order_status` 字段进行去重查询，先了解订单业务的所有流转状态，建立对订单生命周期的基础认知，为后续筛选有效订单做口径准备。

### 分析结论
订单状态共包含 8 种类型：delivered、invoiced、shipped、processing、unavailable、canceled、created、approved。其中 `delivered`（已交付）为平台核心有效订单状态，后续业务分析将以此为主要统计口径。

## 2. 订单表数据量统计
### 分析思路
使用 `COUNT(*)` 统计订单表总行数，了解数据集的整体规模，判断数据量级，为后续分析复杂度做评估。

### 分析结论
订单表总数据量为 **99441 条**，数据规模中等，属于典型的电商公开数据集量级，适合开展多维度分析。

## 3. 订单时间范围探查
### 分析思路
使用 `MIN()` 和 `MAX()` 函数获取订单的最早和最晚下单时间，划定本次数据分析的时间边界，为后续按月、按季度做趋势分析铺垫维度。

### 分析结论
订单时间覆盖平台完整运营周期，明确了分析的起止时间范围，后续可按时间维度拆解订单量、销售额等业务指标。

## 4. 订单表样例数据预览
### 分析思路
使用 `LIMIT 5` 预览订单表前 5 行数据，直观查看字段内容、数据格式、关联ID样式，验证对字段业务含义的理解是否正确。

### 分析结论
订单表字段格式规范，包含订单ID、用户ID、订单状态、下单时间、收货时间等核心字段，数据无明显乱码或格式异常，数据基础质量较好。

## 5. 用户表用户量统计
### 分析思路
使用 `COUNT(DISTINCT customer_unique_id)` 统计独立用户数，了解平台整体用户规模，建立用户量级的基础认知。

### 分析结论
平台独立用户总数为 **96096 人**，用户规模与订单数基本匹配，说明大部分用户为单次下单用户，后续可针对复购用户做专项分析。

## 6. 订单项表数据量统计
### 分析思路
使用 `COUNT(*)` 统计订单项表总行数，了解平台商品销售明细规模，验证订单与订单项的业务关系是否合理。

### 分析结论
订单项表总数据量为 **112650 条**，大于订单表数量，符合“一个订单可包含多个商品”的业务逻辑，后续可通过订单关联订单项分析商品销售情况。

## 7. 支付表总金额统计
### 分析思路
使用 `SUM(payment_value)` 统计平台累计支付金额，了解平台整体交易规模，建立业务大盘的基础认知。

### 分析结论
平台累计支付总金额约为 **1600.89 万巴西雷亚尔**，整体交易规模清晰，后续可基于此计算客单价、人均消费等核心指标。

## 8. 商品表品类及数量统计
### 分析思路
使用 `DISTINCT product_category_name` 统计商品品类和 `COUNT(DISTINCT product_category_name)` 统计商品品类数量，了解平台商品品类丰富度，为后续品类分析划定维度。

### 分析结论
平台共 73 个商品品类，覆盖美妆、家居、运动、母婴、家电、玩具等多个生活场景，品类结构丰富，以日常消费类商品为主，符合大众电商平台的消费定位。

## 本章小结
本章对数据集各核心数据表进行整体摸底探查，全面掌握平台基础业务体量与数据概况：
1. 明确订单状态类型、数据时间跨度、订单总量、独立用户规模、交易总额、商品品类数量等核心大盘指标，搭建起整体业务认知框架。
2. 核验各数据表关联关系与业务逻辑，符合一单多品、用户多账户下单等实际交易特征，数据逻辑合理通顺。
3. 样本数据格式规范，无明显错乱问题，整体数据基础质量达标，能够支撑后续数据清洗与深度分析工作。
